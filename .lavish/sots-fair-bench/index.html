Methodology and limits

Correctness and calibration

All 200 CI cases: IDs 11–30 × ε {299, 30, 5, 0.5, 0.1} × B {300, 1000}. The input hashes and SOTS ε/δ are fixed. DOTS LSSD, DP distance threshold and SQUISH buffer ratio are selected by verified feasible searches, then frozen. These native objectives differ; calibration does not prove globally optimal compression. A common bound does not imply equal point counts.

Continuous distances use FrechetDist.frechet_c_compute, serially and outside timing. Bound slack is max(1e-7, 1e-9 × B). Every measured repeat must keep the same output hash. Before/after checks require byte-identical SOTS coordinates and exactly equal measured distances. Baseline outputs and controls also remain identical.

On the five-point dataset 8, SOTS's distance is 291.547595 at ε=0.5, δ=200. The eight possible endpoint-preserving vertex subsequences have distances 0 or ≥1414.213563. This is why the approved comparison uses an upper bound. SQUISH's pinned capacity≤2 path can omit the endpoint; calibration uses capacity≥3.

Timing boundaries and statistical interpretation

Fresh native processes; one warmup then ten samples; deterministic shuffled round-robin ordering. SOTS times Simplifier::simplify, DOTS its batch index selection, DP recursive selection plus sort/unique, and SQUISH buffer selection. Timers exclude parsing, process startup, output, calibration, Fréchet checks, GUI/traces and profiling. The existing SOTS timer excludes its bounding-box scan. Baseline coordinate and timestamp arrays are prepared during parsing, outside their timers.

No concurrent benchmark workers. Algorithm implementations are sequential and library thread limits are one. No CPU affinity on this shared macOS host; noise and scheduling remain. Marker resolution is 0.0001 ms, material for very small results. Group means are descriptive, not confidence intervals. Paired-reference ratios control some host drift; they do not eliminate it. This is a native-core comparison, not end-to-end latency.

Reproduction and provenance

Build all four targets with the same CMake Release compiler and flags, then run python3 scripts/fair_benchmark.py --phase before --build-dir build-before. Preserve the binaries, build optimized SOTS separately, copy the original baseline binaries into the new build, then run --phase after --build-dir build-after --reference build-before/simplify. See docs/fair-core-benchmark.md for full commands. Raw JSON/CSV and calibration trials are in results/fair-core/.

This portable board uses the trajectory viewer's existing colors and typography. It has no remote scripts, fonts or chart services.
